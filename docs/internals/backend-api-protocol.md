# Backend API & Streaming Subsystem

## Overview
This subsystem handles the HTTP interface for AG-UI, specifically the execution of agent runs and the Server-Sent Events (SSE) streaming of results. It acts as the transport layer between the Flutter client and the Python backend agent.

## Key Components

### 1. API Endpoints
**File:** `src/soliplex/views/agui.py`

The API provides RESTful endpoints for managing threads and runs.

*   **POST** `/api/v1/rooms/{room_id}/agui/{thread_id}/{run_id}`:
    *   **Purpose:** Executes an agent run.
    *   **Input:** Accepts `RunAgentInput` (via `AGUIAdapter`), which includes `messages`, `tools`, and `state`.
    *   **Output:** Returns a `StreamingResponse` (MIME type: `text/event-stream`).

### 2. Request Processing
**File:** `src/soliplex/views/agui.py`

*   **`AGUIAdapter`**: A helper from `pydantic-ai` that parses the incoming request. It extracts:
    *   `run_input`: The structured input for the agent.
    *   `agent`: The resolved agent instance for the room.
*   **Dependencies**: The system constructs `AgentDependencies` (see `backend-agent-state.md`) using `the_installation.get_agent_deps_for_room`.

### 3. Stream Multiplexing
**File:** `src/soliplex/agui/mpx.py`

The response stream is a composite of multiple event sources, merged via `multiplex_streams`:

1.  **Agent Stream:** `agui_adapter.run_stream(...)` - Events generated by the LLM (text chunks, tool calls).
2.  **Emitter Stream:** `agui_parser.agui_events_from_dicts(emitter)` - Events generated explicitly by tools or side-effects (e.g., intermediate state updates).

### 4. Event Persistence
**File:** `src/soliplex/views/agui.py` -> `tee_events`

*   As events flow to the client, they are simultaneously captured in an `events` list.
*   **`tee_events`**: A utility that yields events to the response stream while appending them to the list.
*   **On Completion**: The `save_run_events` method persists the full event history to the database.

## Event Protocol
The stream emits JSON-encoded events adhering to the AG-UI protocol. Common event types include:

*   `RunStarted`, `RunFinished`
*   `TextMessageStart`, `TextMessageChunk`, `TextMessageEnd`
*   `ToolCallStart`, `ToolCallArgs`, `ToolCallEnd`
*   `StateSnapshot`, `StateDelta` (Used for syncing client state updates)

## Current Status
*   **Streaming:** Fully functional SSE streaming with multiplexing.
*   **Persistence:** Automatic archival of run events.
*   **State Sync:** Supports sending state deltas back to the client, though the specific schema of that state is application-defined.
